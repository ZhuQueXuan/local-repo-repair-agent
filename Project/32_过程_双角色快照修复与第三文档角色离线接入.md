# 双角色快照修复与第三文档角色离线接入

日期：2026-10-25。按用户最新决定先完善功能、后统一与最初单Agent比较，承接[21最新顺序](21_规划_RAG与多Agent协作深化.md)。本轮没有启动真实模型或新题效果批次。

## 本轮交付与使用流程

已实现三角色可选流程：用户明确选择文档协作并填写一个问题，程序先调用独立的只读文档查阅角色，登记其带原文的回答，再让修复者初修、独立审查者首审；需要修改时沿用原修复会话返工，再做新版核查。文档角色只有本轮四个受限工具，不继承修复历史或Bash能力，费用、期限、取消与请求归属沿用已有机制。

这是一轮离线接线验收：模型回复、审查发现及用量由脚本预设；文件、Git Bash、评分与新副本补丁重放实际执行。第三角色真实平台上的判断质量和新增成本仍未验证，也没有证明多Agent优于原版。

面板新增“三角色：文档查阅＋修复＋审查（实验）”。真实运行方式下，选该模式并填写“需要文档Agent查清的问题”，使用原上下文与任务状态策略。结果中可查看文档角色、原问题、解释、明确未知、文件哈希和引用原文，以及全角色费用。创建真实任务会调用模型并计费；本轮未替用户点击创建。原离线/单Agent默认保持。

当前是用户在创建时明确请求的一次文档查阅，先于初修执行；尚未实现修复途中动态提问、多次咨询、角色互相委派或并行写入。缺文档时程序不请求模型，生成明确的information_not_found并继续修复；有文档但未找到答案时模型也可返回该状态。来源损坏、角色超时、取消或模型服务异常会按现有异常流程结束，不能伪造成功回答。

## 修复图片导致版本保存失败

[31](31_过程_多Agent新题筛选与离线冻结准备.md)实际复现了Click仓库PNG被UTF-8读取器拒绝。`review_tools.py`现在将受保护的字节读取与文字读取分开；基线/候选文件按原字节复制和哈希校验，文字工具跳过不透明对象。含NUL或不能无损按UTF-8解码的非空对象记为零行；目录结果额外说明content_kind，读取其文字行明确拒绝，不生成行号证据。

旧文本SourceRef的序列化及候选身份算法保持，schema_version仍为1；不向既有候选JSON添加默认字段。空文本仍允许零行；非空零行对象表示不透明文件。快照完整性校验同时核对字节数、行数和哈希。后续工作区改动不污染已封存对象。

权限没有放宽：继续拒绝越界路径、链接/reparse/hardlink、超大文件和新文件越出manifest。单对象仍限256KiB，聚合仍限16MiB。允许保存和审计原有二进制素材；修改实现范围中的二进制内容仍明确拒绝，因为当前补丁收集/干净重放只支持文字补丁，不伪造二进制diff。

## 第三个角色的合同、取证与接线

| 文件/入口 | 已实现职责 |
| --- | --- |
| `scripts/document_agent.py` | `DocumentGrant`绑定父运行、角色、问题、任务、原始源码manifest和文档树版本；`DocumentEvidence`绑定对象/原文行/片段哈希；`DocumentAdvice`区分回答、未找到、冲突及未知 |
| `freeze_documents` / `DocumentSnapshot` | 只从冻结源码manifest筛选根README/变更说明等及docs/doc下的md/rst/txt；最多64个文档，独立复制并逐次核验；不接受用户或模型传任意目录 |
| `DocumentBroker` | 只允许list_files/read_lines/search_text/submit_consultation；分页和文字预算受限；引用必须由实际读取颁发，非空回答必须有引用，冲突至少两条引用 |
| `validate_consultation` / `consultation_context` | 重载时核对快照、原文片段与引用身份；向修复/审查交付精确原文和未经独立证实的解释，不将它注册为测试结果；交接最多6KiB |
| `scripts/document_model.py` / `review_model.py` | 在原受保护请求链上选择文档工具schema，沿用路由、凭据检查、上下文保护和共享费用归属；原审查者仍是六个原工具 |
| `scripts/collaboration_runtime.py` | 独立文档工具会话；保留原始错误，原期限内至多连续3次格式纠正；重复无新取证保护；没有执行环境或递归委派工具 |
| `scripts/collaboration_store.py` | 可选consulting前置阶段、独立角色会话、不可变consultation对象；没有咨询凭证不能进入修复。复用通用对象表，无新增生产表/迁移 |
| `scripts/collaboration_live.py` | 先冻结/查阅，再把来源交给修复者与审查者；接入父取消、期限、全角色记账、成果导出和原四阶段反馈 |
| `configs/multi_agent_documents_v1.json` | 显式文档模式；文档120秒，其余阶段300/120/180/90秒，父期限1800秒；问题另纳入该运行配置和policy_digest |
| `scripts/collaboration_panel.py`、`collaboration_panel.js`、`task_panel.html` | 模式/问题输入、文档角色事件过滤、引用与未知、用量和下载成果；模型文字继续通过textContent显示 |
| `scripts/document_agent_demo.py` | 无真实运行选项的三角色离线演示，全部模型传输替换为脚本，费用只写temp合成账本 |

文档引用明确属于冻结的原始版本，不自动成为任意后续候选的规范证明。修复者和审查者看到相同出处，也必须核实其适用性。当前明确文档清单之外的自然语言规范、远程网站、任意代码定位和语义RAG不在本轮范围。修复者本机Bash仍不是操作系统沙箱，本轮没有扩大到不可信任务。

收尾复核额外修复了提示模板边界：最初把完整咨询JSON拼入Jinja模板，文档问题/原文内的`{{…}}`或`{%…%}`可能被误解析。现在模板只包含程序固定占位符，完整咨询通过独立模板变量一次性作为数据插入。实际五阶段检查使用含`{{ 7 * 7 }}`和条件块的文档问题，验证修复者收到的是原始文字，没有计算表达式或删掉条件块；不靠字符串转义模拟该检查。先前归档保留，最终补正代码与回归另行封存。
