# 同一Agent分阶段自查与离线验收

日期：2026-10-25。承接[21的S+设计](21_规划_RAG与多Agent协作深化.md)、[27的公平比较缺口](27_调研_多Agent主流模式对照与未完成项.md)及[29正式裁决接线](29_过程_审查意见独立裁决与有害返工检查.md)。用户认可推进顺序并要求继续，本轮完成S+运行分支和离线验收，没有新增真实模型身份或付费批次。

## 本轮结果与要解决的问题

现在可以让**同一个Agent先修复，再保留自己的历史进行只读自查，需要时修订并复核**。原先只有单Agent S和独立审查工作流D，缺少这个额外机会相近、上下文来源不同的S+对照。实现S+是准备比较的前提；本轮不能回答它或双Agent是否更有效。

| 方式 | 实际流程与上下文 |
| --- | --- |
| S | 原单Agent初修；原默认和策略保持 |
| D | 原修复会话＋独立审查上下文，需要时在修复会话返工，最后独立核查；现有机制保持 |
| S+ | 初修、自查、修订、自查复核共用一个逻辑session；自查阶段只开放原六个只读工具，历史按时间连续保留 |

S+仍为每个阶段创建不同的role_run_id，便于权限校验、取消和费用归属；这四个ID代表阶段权限主体，**不代表四个独立Agent**。四阶段session_id完全相同，区别于D的修复/首审/最终核查三个会话。

## 上下文边界和公开评分机会

保留自查上下文会比D独立上下文更长。首次集成在复核阶段触发16KB保护；后续又发现格式纠错消息出现后，简单按“最后一条user消息”判定当前阶段会误投影当前指令。现已在S+专用请求视图识别**最后一个程序阶段说明及其后续纠错**，始终保留它们和原始问题/自身推理。只有更早的程序生成阶段清单/固定反馈说明可以变成带原文摘要的索引，原文保存在相应完整轨迹；旧只读观察保留真实tool_call_id和可重读工具参数。不会把历史Bash观察当JSON审查输出解析。

完整raw历史、阶段输入/输出摘要及原工具回执都保留，API视图投影单独记事件。无法缩到保护内就先停止，不预留新费用；原16KB保护未放宽。修订阶段沿用原修复模型上下文策略。当前机制仍可能在更长或不可压缩历史上停止，真实模型对这种跨工具阶段历史的接受情况尚未验证。

S+沿用D的baseline、初修评分、必要时新版评分和最终干净重放，向模型提供同范围已登记公开报告；本轮没有加入保留评价反馈，也没有给S+额外诊断seed或额外在线评分机会。配置对齐时间和机会，实际token/费用不保证相等，后续比较必须如实报告。首修仍使用D相同的基础修复提示。
