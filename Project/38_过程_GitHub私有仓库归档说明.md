目标仓库：[本地仓库修复 Agent](https://github.com/ZhuQueXuan/local-repo-repair-agent)。本轮只整理 Git 归档和获取说明，不改变 Agent 功能，不启动模型或全量测试。

## 保存范围

主目录初始化独立 Git 仓库，主分支 `main`。保存源码、公共配置、阶段文档、题目/评价输入和绝大部分正式实验材料。GitHub 不包含兄弟目录 Job 或医疗项目。部分历史跨项目链接、机器绝对路径仍按原记录保存。

上游 Mini SWE Agent 和已有独立 Git 的 `windowed-empty` 题目源码注册为两个固定版本子模块，保留原工作区和上游历史，不移动、不删除已有 Git 元数据。其他题目冻结源码保持原字节与许可证；见根目录 `THIRD_PARTY.md`。

`.gitattributes` 关闭根仓库的文本换行转换，以避免 Windows 提交/取出时改动冻结输入和报告哈希。提交前将待上传文件逐一与 Git 索引核对，子模块另核对固定提交和工作区状态。

不上传 `.env`、实时 `data/`、`.venv/`、所有层级 `temp/` 和缓存。两份重复大体积资格核验包、三份包含上游测试生成`.env`夹具的回归环境包也保留在本机，逐项见 `GITHUB_SETUP.md`。不改写或重新封存原包，其已有哈希/清单仍留存，因此远端不是所有历史成果的完整逐文件备份。

初次扫描未命中两套真实 API 凭据；发现上述回归包包含配置测试的`.env`文件后，排除原包再进行完整候选集扫描。扫描同时检查普通文件、压缩包内部、两套真实凭据及其Base64表示、明显GitHub/API token和私钥标记；报告只记录文件名/计数，不输出凭据值。不把扫描等同于所有隐私信息都已脱敏，私有仓库仍包含本机路径和开发轨迹。

## 用户如何使用

原电脑继续用当前目录开发、双击原入口即可，不需要改路径或重新装环境。本次仅新增 Git 管理，不重置实时运行记录或共享账本。

在其他电脑获取时用 `git clone --recurse-submodules`，按根 `GITHUB_SETUP.md` 创建环境、安装依赖，再配置本机 `.env`。新电脑使用自己的历史与账本，不能自动继承原电脑52条任务/2016请求或恢复旧失败/暂停任务。

本次未在空白机器重新安装，也未复跑功能回归、浏览器点击或真实模型。当前功能与验证边界继续见 [37](37_过程_Harness阶段暂停与检查点续做.md)，下一项仍为工具/Skills扩展。
