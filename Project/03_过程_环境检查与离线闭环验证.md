## 验证怎么做

正式教学任务为 [空购物车任务](../examples/cart-empty/README.md)。原始代码故意保留空输入报错，用于之后重复实验；测试包含空输入、单项、多项、零价格和小数价格五种情况。

在任务 `temp/` 中创建工作副本。使用上游 `DefaultAgent`、`LocalEnvironment` 和 `DeterministicModel`，预先指定五步：读取代码、运行测试重现错误、补上reduce初始值、再运行测试、发送提交标记。没有模拟或修改上游方法，没有调用外部模型。

单任务配置最多6步、120秒、每条命令30秒；另一次检查设置最多2步，验证限制退出。

| 检查 | 实际结果 |
| --- | --- |
| 原始任务 | 5项测试，4通过、1项TypeError |
| 预设修改后 | 5项测试全部通过 |
| 执行闭环 | 5次固定模型查询，结束状态Submitted |
| 反馈进入历史 | 4条执行观察，包含修复前错误与修复后通过结果 |
| 轨迹保存 | 修复轨迹和步数限制轨迹均已读取核验 |
| 最大步数 | 实际2步后LimitsExceeded |
| 外部模型请求与费用 | 0次、0费用；轨迹api_calls字段在此记录固定模型查询次数，不是外部请求数 |

当前上游 `LocalEnvironment` 采用 `shell=True`；在Windows中实际使用原生命令解释器cmd.exe。本次预设命令是适配Windows的Python命令，不代表通用Bash命令已兼容。真实模型阶段需选择并验证Bash执行方式或Linux运行环境。
