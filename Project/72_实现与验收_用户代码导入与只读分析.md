# 72 用户代码导入与只读分析：实现和有边界的验收

日期：2026-10-30。用户批准按71实施，上传后先分析并给有位置依据的报告，修复另外启动。本轮完成A1/A2的本机工程闭环，版本1.1.0；A3独立复核未实施。既有修复实验仍有单、双、三角色，三角色为文档查阅→修复→审查，原来就存在，并非当前只剩两个。

## 用户可使用的流程

双击根目录“启动任务面板.cmd”，首页导入单文件/项目ZIP或公开GitHub链接→确认文件范围和关注问题→确认原模型外发说明→开始只读分析→查看报告/原文位置/未知和覆盖/费用，取回JSON或文字报告。固定题目与原协作开关保留在顶部“演示与修复实验”中。

导入与模型调用分开：导入只在本机准备来源快照，GitHub先解析ref为commit再获取其归档；私有仓库不接受token链接，可上传ZIP。报告生成不等于测试通过，也不等于全仓无问题。用户代码无命令执行环境；没有启动自动修复。

## 实现与复用

- `analysis_sources.py`：单文件/ZIP/固定commit获取、路径和大小校验、排除清单、原字节与来源哈希。ZIP拒绝越界、Windows别名/反斜杠改写、大小写重复、链接、加密和特殊文件；不解包嵌套压缩包。默认排除.env/疑似凭据、依赖/生成物/运行数据、二进制与非UTF-8文件。自动敏感识别仍可能遗漏。
- `analysis_runtime.py`：独立analysis任务与严格报告合同，只有目录、文字搜索、按行读取和提交报告四工具。范围与来源摘要绑定；引文由程序根据实际读取生成，未知/伪造引文拒绝，最终再校验源码完整性。每次读取最多80行，单段输出受字节限制；保留完整轨迹，模型请求保留原始任务及近期完整工具交互，旧片段可重读。
- 复用现有队列、幂等键、进程生命周期、取消/等待守护、历史、来源安全读取、成果哈希和完整下载；无数据库结构迁移。新的分析种类不伪装成有标准答案的固定修复题。
- 模型继续使用原北邮优先/DeepSeek备用及SharedBudget；读取模型沿用现有只读请求能力标签，产品明确只读分析而非已有第二审查角色。原每请求每平台最多一次、认证/余额停止、共享费用与每任务300秒保持；没有按任务结果循环重跑。
- `analysis_panel.html/js`：范围预览/选择、显式外发确认、幂等创建、历史/取消、原文引用、费用/覆盖/未测试说明；所有模型正文用textContent显示。原`/experiments`保留单/双/三角色，两个页面的列表按种类区分。

开源取舍沿用71核查：复用当前MIT Mini SWE Agent 2.4.6与本机扩展；GitHub官方commit/归档接口。没有升级底座或引入依赖。python-multipart当前主线Python要求与本机3.10不符，首版使用独立二进制上传接口；Tree-sitter和整体Agent SDK迁移均非本轮必需。

边界：上传20MiB，ZIP≤5000条目/声明解压总量100MiB，单文件256KiB，可分析≤1000文件/8MiB，过长路径排除；这些是程序限制，不代表大仓性能或全语言完整理解已验证。仅https github.com仓库首页，ref另填；重定向仅api.github.com/codeload.github.com，不读取仓库指令扩大权限。只保留纳入快照的文件原字节、输入ZIP哈希和排除原因，不保存排除的敏感正文。
