# 本地任务管理与最小展示

日期：2026-10-18。用户认可先完成任务管理，并明确希望之后深入多Agent与RAG。本轮完成本机单worker服务、最小页面、启动入口与功能验收；多Agent新机制未实现，方案见[21](21_规划_RAG与多Agent协作深化.md)。

## 解决的问题与实际效果

以前要找各轮配置、temp身份、summary和实验目录，手工判断有没有正常提交、补丁是否通过。本轮增加稳定run_id、持久状态和事件，把这些结果接入一个本地入口。打开页面默认不调用模型，可以只看历史或重放补丁；主动选择真实运行后才请求模型。

双击根目录[启动任务面板.cmd](../启动任务面板.cmd)，或访问已启动的[本地面板](http://127.0.0.1:8765/)。面板能选择固定任务和原版/上下文/按变化检索策略，排队、取消、查看动作、diff、外部验收和用量；没有未结束任务时可停止服务，之后重新启动，历史仍可查看。

本轮没有改旧run_task_batch、Mini上游源码、旧实验配置、冻结或claim。服务通过已有组件运行Agent和评分；新的运行身份与输入快照独立保存。没有安装依赖或外部发布。

## 改动前后的流程

新流程为：页面/接口创建任务 → SQLite立即保存run_id与幂等请求身份 → 单worker接手 → 冻结输入、准备独立副本与修复前检查 → 离线应用历史补丁或真实Agent执行 → 导出合规补丁 → 独立验收及新副本重放 → 保存正式成果、哈希与终态。

运行状态、Agent退出和修复验收是三个独立字段。例如旧排序题仍显示运行结束、LimitsExceeded、补丁通过；中断且没有报告的任务显示验收未知。历史字段缺失保留未知，17轮离线恢复标记和缺失精确耗时保留，没有把它补算成完整运行时间。

| [task_service.py](../scripts/task_service.py:22) `Supervisor` | 一次启动一个执行进程；进程锁区分旧worker仍在执行与已中断。重启管理器不会重放已执行命令或重复请求 |
| [同文件](../scripts/task_service.py:58) `make_handler` | 只监听127.0.0.1的接口；检查Host、Origin和页面令牌；只允许列入清单的任务、策略和成果路径。活动任务未结束时拒绝停服 |

| [同文件](../scripts/task_service_worker.py:25) `RunBudget` | 每次请求仍通过原SharedBudget；HTTP前把共享账本ticket关联run_id事件，不重置或复制出一份新预算 |
| [同文件](../scripts/task_service_worker.py:76) `ServiceModelHooks`及环境hooks | 查询前检查取消；响应计费后、执行动作前再次检查；动作与用量逐次写事件。不能仅等下一次query才响应取消 |
| [同文件](../scripts/task_service_worker.py:38) `attach_process_lifetime` | Windows Job Object约束worker及其子进程的生命周期；worker被强制结束后清理所属子进程。它不是文件/网络安全沙箱 |
| [同文件](../scripts/task_service_worker.py:155) `collect_patch` | 只接受原清单中的已有实现文件；明确拒绝新增/删除/越界改动，保留测试与问题说明保护 |
| [task_panel.html](../scripts/task_panel.html) | 无外部依赖的中文页面，轮询任务/事件；分别呈现三类成绩、用量、未知占位、补丁与测试报告 |
| [launch_task_panel.pyw](../scripts/launch_task_panel.pyw)及根启动文件 | 复用已运行面板，或以现有Python后台启动并打开浏览器；日志写入temp，启动本身不请求模型 |
| [test_task_service.py](../scripts/test_task_service.py) | 新增23项检查，区分模拟模型、实际本机HTTP、Bash超时与真实文件范围验证 |

SQLite和新成果位于`data/task_service/`；每次运行正式文件在`runs/<run_id>/`，过程日志在根temp，工作副本沿用各题temp。历史实验原件仍位于experiments，接口从注册的成果路径读取，不接受任意本机文件路径。

### 实施中暴露的问题及修正

首轮页面离线任务`f1aad4fbcaa84f6e82ec270a3ec5520b`因日志与执行器共用已存在目录而FileExistsError；该失败记录保留，修正目录创建后以新身份验证，没有覆盖失败任务。

双击入口也做了实际检查：初始PowerShell入口在执行检查时文件已不可用，未确定原因，最终改为直接使用既有Python后台启动；cmd的换行/编码首次不兼容也已修为ASCII及CRLF。最终cmd启动、页面停服、再次启动和页面离线任务均实测通过。没有安装软件、调整系统执行策略、代理或防护设置。

真实模型运行结束后，补充了故障检查、停服按钮、启动入口适配与部分中文呈现；没有重跑模型。随后补充了平台切换前的取消检查及离线回归，避免取消后仍发起备用请求。真实运行的旧输入快照独立保留，最终代码另经离线检查与实际页面重放验收，不宣称两个快照逐字相同。

页面快速切换记录时还加入加载态、选择版本及过期响应过滤，避免上一任务的异步结果写到当前视图；实际重新选择真实任务并打开补丁后，核对了run_id、用量和more_itertools修复路径一致。界面证据见[截图](../experiments/task_service_20261018/task_panel.png)。

过程验收汇总在[本轮实验目录](../experiments/task_service_20261018/)，含进程检查记录、最终检查日志和最终证据汇总。服务数据库与各run正式成果是持久工作数据，不只保留在temp。
