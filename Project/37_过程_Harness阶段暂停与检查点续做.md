# Harness阶段暂停与检查点续做

2026-10-26。承接[36任务卡](36_过程_Harness任务卡与运行中要求补充.md)，继续落实用户已认可的[35 Harness框架](35_调研_Agent_Harness主流方案与项目演进建议.md)。本版实现双/三角色的阶段暂停、不可变检查点、关联新身份续做及链路费用展示。用户要求功能先行、之后集中系统测试，本轮没有新增正式测试文件、完整回归、效果批次或真实模型请求。

## 现在的使用流程

1. 打开原`启动任务面板.cmd`或本机8765入口，新建真实双/三角色任务时先开启任务卡，再勾选“允许双/三角色在阶段结束后暂停与续做”。两个开关默认关闭；已有旧任务不会被自动加入这个机制。
2. 执行时点击“在当前角色完成后暂停”。程序等待该角色完整结束，包括模型动作、候选登记和该阶段的本机检查；不会截断在途模型请求或Bash命令。角色失败或超时时按原规则失败收尾，不伪造一个可续做检查点。
3. 安全暂停后，原记录标记为“已暂停”，显示下一阶段和剩余任务运行时间。此时执行器会收尾退出，旧任务卡、费用与候选保留只读。
4. 在续做区域补充要求，点击“从检查点创建新任务并继续”。程序先核对清单、文件和当前代码，然后创建关联的新任务，从未完成阶段接着做；原暂停记录不改成运行中，也不覆写旧失败。

排队时也可请求暂停：执行器准备必要环境后，在第一个角色前暂停。若所有角色已结束、已进入最终收尾，则优先正常完成，不为了暂停再制造一个阶段。暂停期间不消耗剩余任务活动时间；续做继承已剩余的秒数，不重新给整套30分钟额度。该功能没有引入费用总额上限或重置共享账本。

当前仅支持普通双角色和三角色、开启任务卡的新运行。单Agent命令中途恢复、S+自查和人工缺陷诊断暂不开放。暂停点是一个完整角色的边界；需要立即终止时仍使用原取消功能，取消后不能作为暂停身份恢复。

## 保存和恢复什么

检查点保存冻结输入/运行代码哈希、下一阶段、剩余时间、当前候选与独立报告、文档出处与精确引用、各角色已完成结果、修复者已确认提交的消息历史、工具输出归档与任务事实。恢复时只复制明确登记的实现文件、工具文字输出、上下文文字归档及一份受限工作笔记，不搬入临时脚本、依赖、缓存或旧.git目录。

旧工具输出的文件哈希会校验，恢复后工具输出序号接续，避免新输出覆盖0001等旧凭证。上下文归档必须与对应原始消息字节一致；任务状态中的原始文件指纹、重复读取记录等保留。工作副本另建在新任务自己的目录中，从检查点副本恢复，而不是直接沿用可能已被外部修改的旧工作目录。

完整检查点文件总量上限64MB、清单上限16MB，超过时拒绝保存，不截断恢复所需历史。不存在可用提交证明、存在结果未确认的逻辑请求、候选与工作副本不一致、受保护检查被改动或注册证据损坏时，都不生成可继续身份。清单和逐文件哈希校验使用既有普通文件/硬链接/路径保护。

模型上下文属于**验证后导入的历史**，不是平台端续发旧请求。新会话只执行剩余动作；旧路径和旧引用只作历史说明，当前反馈提供新的绑定。文档、候选、报告、证据、意见和回应会重新绑定到新身份及新角色，保留明确的来源—目标ID映射；继承阶段在界面单独标注，不算本段新模型成功。

若暂停后运行代码、配置或原任务输入改变，本版直接拒绝续做，提示冲突项。没有跨版本自动迁移，也不能修改旧freeze哈希来消除保护。旧33/v7诊断和旧失败/取消/中断身份没有这个可续做标记，仍不可恢复。

## 一次暂停点只创建一个续做任务

请求使用固定幂等键，数据库以来源暂停点为唯一键。重复点击同一内容返回原子任务，换键不允许另建第二个子任务。同一键却改任务卡也会拒绝。源任务payload与角色结果不被修改，来源关系记录在新的子任务及附加关联表中。

准备过程中先创建不可调度的`preparing_continuation`身份，导入/核验完才进入queued。导入失败保留失败身份和关联，不放回队列、不自动另建。执行器尚在收尾、仍持有worker锁时返回冲突，等待明确重试；进程崩溃留下的不完整准备身份也不会被Supervisor自动执行。

新任务继续使用原共享账本，每个模型请求归属新的角色/任务。页面既保留本段费用，也展示当前段及全部前段的累计平台尝试、已知估算和未知费用。旧段费用不会被转移或重置；未知平台价格仍未知，不把占位额说成实际扣费。最多64段，防止异常循环来源链。

## 必要基本检查的实际结果

- 一条离线链路实际经过文档→暂停/新身份→修复→暂停/新身份→首审→暂停/新身份→返工→暂停/新身份→最终核查。各角色模型调用仍为3/2/2/2/1，共10个**合成**调用，没有因恢复重跑已完成角色。四份源记录保持paused且payload不变，最终修复passed、审查approve。
- 同一链路核对检查点文件篡改先拒绝、且不创建子身份；恢复精确原字节后才继续。相同键返回同一子任务，不同键被拒绝。
- 对输出归档补充一条定向检查：首修后暂停，再执行剩余阶段。原3份归档字节保持，新输出序号从后续编号开始，原TaskState文件基准保持，来源两段累计仍为10个合成调用。不是新增Agent题目或真实成绩。
- 两次使用原有演示时，模型响应/用量均固定；本机源码修改、问题10/10、针对性4/4及干净补丁重放实际执行。全量检查仍保留原659/660计时差异，不说全绿。
- 原5项基本兼容检查通过：批准分支、期限、取消、Schema保护和默认创建。没有跑全量默认/适配回归，历史34的301/405不能充作本轮代码成绩；不新增正式测试项目。
- 隔离HTTP实际核对认证、排队暂停意图、从文档暂停点创建唯一子任务、只在新卡补充要求、源payload不变、继承角色标记及来源链2次合成调用。临时服务没有Supervisor/worker，队列没有执行模型；检查后取消临时队列并正常关闭服务。
