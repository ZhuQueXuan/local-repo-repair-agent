静态核对上游 2.4.6 的 tests：**41 个 test 文件、460 个 test 函数**。参数化后一个函数会生成多个执行用例，不能把 460 当成本机实际运行总数，也不能把测试通过率当 Agent 修复成功率。

当前清单将文件分成 28 个原样候选、3 个适配诊断、10 个不进入本机离线配置的文件。原样候选中还在收集后排除 41 个具体执行用例，逐条记录原因：13 个异步 inspector、11 个 slow/容器相关、2 个 POSIX 固定轨迹、4 个缺 Portkey SDK 的分支、11 个需要已安装 CLI 或真实子终端的分支。没有用一个“忽略失败”的开关代替分类。

十个整文件排除项是实际付费 API fire 测试、Docker/Singularity/bubblewrap/SWE-ReX/Modal/contree 环境、Portkey 两种接口及 ProgramBench 容器集成。原因见 [upstream_regression.json](../configs/upstream_regression.json)。不因本轮回归启动容器、下载镜像或模型数据，也没有安装这些未使用的可选组件。

## 现在怎样运行

在主项目目录运行，或双击根目录的 `运行离线回归.cmd`：

```powershell
# 默认：上游原样离线检查 + 本项目扩展检查
.\.venv\Scripts\python.exe -B scripts/run_regression.py

# 仅原样上游检查
.\.venv\Scripts\python.exe -B scripts/run_regression.py --scope upstream

# 真实 Git Bash 适配诊断；当前有七项差异，预期退出码为 1
.\.venv\Scripts\python.exe -B scripts/run_regression.py --scope upstream --upstream-profile adapter

# 三类一起运行，各自统计；当前同样会因适配差异退出 1
.\.venv\Scripts\python.exe -B scripts/run_regression.py --upstream-profile both
```

每次使用新的 `temp/regression/<时间_UUID>/`，打印日志和 summary.json 的位置，不覆盖旧运行。默认命令的成功只代表原样适用子集和本项目扩展通过，**不包含七项适配诊断失败已解决的含义**。双击入口已提供，底层默认命令已经实测；用户本人双击操作尚未验收。

## 改动文件与关键实现

| 文件 | 作用 |
| --- | --- |
| [run_regression.py](../scripts/run_regression.py:64) | 固定版本/文件分类核对，生成清单，隔离环境后串行启动各组检查，保留日志与源码/数据前后哈希；任一已选组失败就返回非零 |
| [upstream_regression_support.py](../scripts/upstream_regression_support.py:11) | 上游测试进程中的网络/私有配置和写入范围检查，保留临时目录，逐项登记执行与排除结果 |
| [UpstreamResults](../scripts/upstream_regression_support.py:48) | 分类收集、记录结果；只有显式 adapter 模式才替换测试模块的执行环境绑定 |
| [upstream_regression.json](../configs/upstream_regression.json) | 上游版本、原样与适配文件清单、按文件和用例排除的具体原因 |
| [test_deepseek_budget.py](../scripts/test_deepseek_budget.py:106) | 修正并发测试的“必须一次填满两份额度”假设，强化返回凭据与落盘记录一致、总预留不超额和后续请求拒绝的断言 |
| [运行离线回归.cmd](../运行离线回归.cmd) | 使用已有虚拟环境调用默认入口，保留退出码并停留显示结果 |

原样模式不替换任何 Agent、模型或执行环境实现。为能在没有 Windows 控制台的测试进程中导入交互模块，使用 prompt_toolkit 自带的 DummyInput/DummyOutput 测试会话；保留上游已有 mock 和断言，不新增假的模型成功响应。

适配模式复用 `test_default.py`、`test_interactive.py`、`environments/test_local.py` 的原始测试函数；只把这些测试模块的 LocalEnvironment 构造入口绑定到现有 GitBashEnvironment，补上构造参数设置。命令由实际 Bash 子进程执行，没有将输出改写为预期值。这是**复用上游断言测试本项目适配器**，不是证明原版 LocalEnvironment 在 Windows 上通过。

测试进程不继承提供商凭据，禁止 dotenv 自动向上查找本项目私有配置；全局测试配置和系统临时目录改到当次 temp。上游 Python 进程在解析域名/建立连接前阻断网络，禁止写出当次目录及读取其外的 .env。临时目录退出时保留，pytest 不清理旧目录，未执行批量或递归删除。测试支撑层实际自检了网络解析拒绝、私有配置读取拒绝、越界写入拒绝、目录删除拒绝及临时目录保留，5 项均通过。

这些措施是测试进程的保护，不是任意程序的 OS 沙箱。Python 子进程/实际 shell 使用的是已核对的固定上游测试命令；不向此入口开放用户上传的任意测试代码。初始化和关闭 Windows 事件循环所需的本地 IPC 不属于模型调用。

## 实际结果与失败发现

| 检查 | 实测结果 |
| --- | --- |
| 默认入口，上游原样适用子集 | 301 通过，41 个具体用例按声明原因排除；退出码 0 |
| 默认入口，本项目扩展 | 236 项，235 通过、1 项实际文件 symlink 权限跳过；退出码 0 |
| 默认入口整体 | 退出码 0；检查期间跟踪的 1,509 个上游源码/测试、本项目源码/配置和 data 文件哈希未变 |
| Git Bash 适配诊断 | 176 项，168 通过、7 失败、1 个 POSIX 进程组用例在 Windows 跳过；退出码 1 |
| Agent 控制流程复用 | default 的 48 项和 interactive 的 108 项共 156 项均通过，使用固定模型响应；没有真实模型调用 |
| 并发断言修正后的定向压力检查 | 合成账本上连续 30 次通过，无失败或错误 |
| 测试进程保护自检 | 5 项通过；不发出实际 DNS/API 请求 |

第一轮广泛离线候选运行保留了 **339 通过、152 失败、1 跳过、26 排除**：大量 POSIX shell 用例在原生 cmd 下无法识别提交标记，耗尽固定响应后抛 IndexError；另外有 Portkey 缺依赖和 CLI 未安装/子进程无控制台问题。后续将“原样兼容”和“实际适配”拆开，未修改上游测试或生产类来取得通过。

适配诊断仍有七项失败：

| 差异 | 用例数 | 当前结论 |
| --- | --- | --- |
| 配置 env 和进程环境变量没有按上游约定传给命令 | 3 | GitBashEnvironment 当前使用受限环境变量集合，未实现上游的通用 env 透传能力；不能把全部变量直接透传作为测试修复。本轮只记录接口差异，后续若需要此能力应明确安全边界 |
| pwd 返回 POSIX/MSYS 路径，断言要求原生 Windows 路径 | 3 | 是路径表示差异；不能仅凭字符串不相等判断工作目录失效，本轮没有伪造输出使断言通过 |
| 超时结果缺少 extra.exception_type | 1 | 现有适配器返回 returncode=-1 与 exception_info，但未保持这项上游结构化字段约定；记录为待处理的兼容缺口 |

还有一项与上游无关的已有并发测试在集成时偶发 `1 != 2`。源码使用非阻塞文件锁，锁忙允许返回 OSError，40 次并发机会并不保证正好用满两份额度。原断言混淆了“不超额”与“每轮必填满”。现在先核对并发成功数 1—2、返回凭据与落盘请求集合完全一致，再在无竞争时补足两份并确认额外预留被拒绝。没有放宽安全总额，也未修改 SharedBudget 或正式账本。该次失败日志保留，之后的 30 次定向检查和默认完整回归通过。
